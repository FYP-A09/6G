Digital Twin Assisted Dynamic Network Slicing for AI-Native 6G Networks

Can a 6G network share bandwidth between eMBB, URLLC and mMTC better if it knows what traffic is coming next? We test this on real traffic from all 10,000 cells of Milan, with a temporal graph neural network for forecasting and multi-agent reinforcement learning for allocation.

Key results

0.76MARL reward, flat from 9 to 100 cells (single agent: 0.41 → 0.27)
19,332parameters in the shared MARL actor at every network size
+19%city forecaster over persistence on all 10,000 cells (eMBB)
393.6 Mrows × 122 columns in the Digital Twin dataset

What did not work, reported as such: self-supervised embeddings gave no gain over raw features, and giving the forecast to the MARL agent did not improve it. The forecast helps through an expert allocation policy instead (about +0.05 reward at every size).

How it works

  • Real data: Telecom Italia Milan traffic on the real 100 × 100 grid; internet, calls and SMS mapped to eMBB, URLLC and mMTC.
  • Calibrated QoS: latency against load fitted to a public 6G RAN telemetry dataset, with load-coupled interference between neighbouring cells.
  • Forecasting: GraphSAGE + GRU temporal GNN; a city-wide version trained on random grid patches with per-cell scaling.
  • Allocation: one shared actor per cell with a neighbourhood critic, compared with a centralised agent and expert rules.
